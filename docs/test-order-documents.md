# Development order documents
Customer: order detail > Order documents > Download order summary. Admin: Orders > Manage > Order documents. PDF generated on the backend using saved order snapshots and current order/refund status. No database changes or external services. Download endpoints require an authenticated customer who owns the order or the existing administrator permission/MFA gate. Responses are private/no-store. Summary is available for all order states; shipping label and packing slip require an active confirmed test order with items and complete saved address. All generation is disabled in production.
A4 order summary and packing slip, 4 x 6 inch single-page label. No carrier barcode, real dispatch, GST invoice or payment receipt. INR is used rather than the rupee glyph. Standard built-in PDF fonts currently support Latin-script text only; unsupported text or overflowing label returns 422 rather than corrupting the address. Multilingual fonts, approved legal tax fields, carrier labels and commercial shipping policies are launch prerequisites. Files are generated on demand and not stored on the server.
Install the pinned PDFKit dependency with npm install, then npm run build. Backend tests use synthetic records and validate role/ownership and PDF output. Visually inspect the local downloaded PDFs before approving the feature.
