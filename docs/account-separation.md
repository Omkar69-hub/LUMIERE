# Account boundaries
Customer login routes to /account; administrator login routes to /admin, subject to existing MFA and server authorization. An administrator opening a customer account, bag, wishlist, checkout, personal order or support page redirects to /admin. Customers cannot access administrative endpoints. Customer APIs reject admin sessions; all customer data remains scoped to the authenticated customer ID. Admin profile editing stays in Admin Studio. Public storefront remains available to administrators for preview; purchasing requires a customer session.
Sign-in, logout and password reset clear client queries; a non-sensitive browser storage signal reloads other same-origin tabs when the session changes. One browser profile shares cookies across tabs; use separate browser profiles or an incognito window for simultaneous admin and customer testing. No user roles, orders or database records are changed by the routing update.
Regression coverage: browser role redirects and account switching, authenticated API isolation and order ownership. Run in an isolated test database, never on development data.
